核心价值

为什么需要基石

把合同、判决书、证据材料发给云端 AI 前，敏感信息去了哪、谁能看、如何还原——基石把这三件事一次解决。

📴

纯本地离线

从识别到替换全程在本机完成，不发起任何网络请求。模型与词典随安装包分发，防火墙全阻断环境下功能完整。

🎯

三层识别引擎

规则（正则+校验位）兜底精度，词典覆盖上下文，NER 模型补齐长尾。仲裁器按层优先级与置信度分桶，宁可漏标不可错标。

👁️

人工可控

所有识别结果进映射面板，支持启停、删除、自定义、同名拆分。低置信度默认进"待确认"不生效，导出前弹确认。

↩️

可回溯还原

脱敏映射经 AES-256-GCM + scrypt 加密导出。AI 改完文档后，凭映射+密码一键还原，并自动生成"未还原项"报告。

功能模块

四个模块，一条安全流水线

从识别到替换，从加密到还原——每个环节都为"隐私不出机"而设计。

MODULE 01

三层识别引擎 + 仲裁器

同一段文字，三种视角交叉验证。规则层负责"确定的"，词典层负责"有上下文的"，NER 层负责"没见过的"，仲裁器把它们对齐成不冲突的结论。

  • 规则层：身份证 GB11643 校验位、银行卡 Luhn、统一社会信用代码——校验不过直接丢弃，从源头防误报
  • 词典层：姓氏 / 民族 / 提示词 / 司法停用词，"原告 X 某"这类上下文模式精准命中
  • NER 层：RoBERTa-cluener2020 转 ONNX，识别长尾人名 / 机构 / 地址，默认进待确认
  • 仲裁器：层优先级取舍 + 相邻实体碎片合并，避免"莲花街|道|办事处"被切成三段

MODULE 02

Word / PDF / 扫描件，格式保真

脱敏最怕"字换了、版乱了"。基石按文档结构的最小单元替换，样式、表格、页眉页脚原样保留，导出与原文档排版零差异。

  • docx：run 级替换，加粗/字体不动；跨 run 命中（如"张三"被加粗拆开）也能正确合并替换
  • 文字型 PDF：PyMuPDF redaction + 字号自适应，代称太长自动缩字号防溢出
  • 扫描件 PDF：RapidOCR 识别（DPI 200 保召回），OCR 结果缓存避免二次识别，多文件并行自适应线程
  • 映射按键长降序执行，"张三丰"不会被"张三"吃掉成"甲某丰"
✓
MODULE 03

天干地支代称 + AES 加密映射

同一原文在同批次里只对应一个代称，跨文档一致。代称本身不含任何原始信息，映射关系加密落盘，密码不明文存储。

  • 代称序列：十天干 → 十二地支 → 天干+序号（甲某…癸某→子某…亥某→甲某2…）
  • 类别后缀：人名"某"、公司"公司"、单位"单位"、地址"地址"，一眼看出类别
  • 映射文件 AES-256-GCM 加密 + scrypt 密钥派生，密文无明文残留
  • 密码错误拒绝解密，无找回通道——丢密码等于丢映射

MODULE 04

回溯还原 + 未还原项报告

脱敏文档喂给 AI 改完之后，还能安全地变回来。拖动下面的滑块，直观对比"AI 处理后的脱敏文"与"还原后的原文"。

  • 凭"AI 处理后文档 + 加密映射 + 密码"三要素还原
  • 按代称长度降序逆替换，docx / txt / md 均支持
  • AI 改写、删除的代称自动进"未还原项"报告，随还原文件导出
  • 文档名不在清单只警告不拒绝（AI 产物的哈希本就不同，属预期）

使用场景

什么时候，你需要基石

01

📤 把案件材料发给云端 AI 前

想用大模型分析合同、起草文书、梳理证据，又怕当事人隐私泄露？先用基石脱敏，AI 只接触代号，分析完再还原。

02

🤝 对外提供证据 / 案卷副本

向对方当事人、调解机构、第三方提供材料时，隐去无关个人的身份证号、联系方式、住址，满足最小必要原则。

03

📊 数据共享与教学研究

判决书、合同用于教学、培训、研究或内部案例库建设，批量脱敏后安全共享，保留文书结构与争议焦点。

04

🗄️ 合规归档与存储

需长期留存但不宜明文保存个人信息的文档，脱敏归档；映射加密另存，需要时凭密码精确还原。
